## Autoscaling triggers

Every HPA (`autoscaling/v2`) scales on **CPU utilization > 70%** OR
**Kafka consumer lag > 500 messages** (the portal has no Kafka consumer, so it
scales on CPU only).

- CPU: `Resource` metric `cpu`, `averageUtilization: 70`.
- Kafka lag: `External` metric named **`kafka_consumergroup_lag`**, targeted at
  `AverageValue: "500"` (500 lagging messages per replica). This metric is
  expected to be published to the Kubernetes external-metrics API by the
  **Prometheus Adapter** (`prometheus-adapter`), sourced from
  `kafka-exporter` / Strimzi broker metrics. Each HPA selects its own consumer
  group via `matchLabels.consumergroup: <service-name>`.

  > Prerequisite: `prometheus-adapter` must be installed with a rule that maps
  > `kafka_consumergroup_lag` into the external metrics API, and `metrics-server`
  > must be running for the CPU metric.

## GPU deployments

`fraud-ring-engine`, `document-forgery-engine` (NVIDIA T4) and `llm-service`
(NVIDIA A100) request `nvidia.com/gpu: "1"`, set `runtimeClassName: nvidia`,
tolerate the `nvidia.com/gpu` taint, and use a `nodeSelector` targeting the
matching accelerator pool (`cloud.google.com/gke-accelerator` + `ei-ads/gpu-pool`).

## Generation and validation

Manifests are generated by `scripts/k8s/generate_deployments.py` and validated by
`scripts/k8s/validate_deployments.py`:

```bash
python3 scripts/k8s/generate_deployments.py
python3 scripts/k8s/validate_deployments.py
```

The validator uses PyYAML `safe_load_all` (multi-document safe) and asserts
replica counts, ports, probe paths, both HPA triggers, and GPU settings.

## Sandbox limitation

These manifests were **validated for YAML/structural correctness only**. They
were **not** applied to a live cluster — no Kubernetes/OpenShift cluster is
available in the sandbox, and applying them additionally requires the images to
be built/pushed (task 35.x) and `prometheus-adapter` + GPU node pools to exist.
Live apply and `/healthz` assertions happen at the checkpoint in task 37.
